How to use this board

This is our shared tasklist for winning the STIHL RFP — every task from the audit, organised by phase, with estimates, dependencies and hard dates. Whatever you do here, the whole team sees it instantly.

  1. Say who you are — the “I am” dropdown in the header. Your ticks and comments carry your name.
  2. Tick a task done — click its checkbox; it shows “✓ your name · date” for everyone. Untick to reopen it.
  3. Assign a task — every task belongs to the Team by default; use the dropdown on the task to hand it to one person (pick Team to give it back to everyone).
  4. Add a task — “＋ Add task” at the bottom of any group; everyone sees it live. Added tasks (and only those) can be deleted.
  5. Discuss — 💬 opens a comment thread on that exact task. Type @ to tag someone (e.g. @leonel) — tagged people get a notification.
  6. Notifications — the 🔔 in the header collects your mentions and replies from all three pages, plus everything assigned to you.
  7. Filter — All / Open / Done and Team / Martin / Leonel / Mike, in the top bar.

§6 change mgmt · §5.2 · §7proposal~2 h

The target topology, so uptime is not only high but consistent. Today: one production instance; staging not built (I-xmu0hw5a2).

  • 2 × production for the dealer sites (front) and 2 × production for the platform (back), behind the edge. If one instance fails, the other carries the network and the dealer never notices.
  • 1 × staging for each, kept in step with production. Every change is rehearsed there before it touches a dealer — and it is the third fallback: if both production instances were lost, staging can be promoted.
  • What this buys STIHL: a rollout that never goes straight to live, UAT links for dealers on real infrastructure (X-10), and an honest answer to "what happens when it breaks", which the audit currently marks as a gap.
  • Cost is small at this scale (the capacity report has the numbers); the handoff doc estimates the dev/staging/prod split at about US$70/month.

Do not claim this as built until it is. Describe it as the rollout topology with a date, and run the pilot on it.
